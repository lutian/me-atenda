Detalhe do Plano de Projeto: AI Outbound Sales Agent (Twilio + RAG + FastAPI + Streamlit)
1. Visão Geral da Arquitetura
O projeto será estruturado em um monorepo/multi-container Docker com três serviços principais:

backend (FastAPI): Orquestrador principal. Gerencia a API REST, os Webhooks da Twilio (voz/media streams), a engine de conversação baseada em LLM, o pipeline de RAG com PostgreSQL (pgvector) e a fila de chamadas unidirecionais.

frontend (Streamlit): Painel administrativo leve para cadastrar produtos/serviços (alimentando a base de RAG), gerenciar a tabela de leads/fila e monitorar o status e transcrições em tempo real.

database (PostgreSQL + pgvector): Armazenamento relacional de leads, histórico de chamadas, áudios/transcrições e os embeddings dos produtos/serviços para consulta via RAG.

2. Especificação por Módulo para a Codex
A. Banco de Dados e Modelagem (PostgreSQL)
A migration deve criar tabelas otimizadas para o fluxo comercial:

products: ID, nome, descrição geral e chunks de texto vetorizados (pgvector) para o RAG do produto/serviço.

leads: ID, nome, telefone, empresa, status (pendente, ligando, sucesso, sem_interesse, caixa_postal, numero_errado, atendimento_automatico, falha_tecnica).

calls: ID, lead_id, product_id, status_final, duracao_segundos, audio_url (caminho local ou S3), transcrição_json (histórico completo de mensagens/turns da conversa).

B. Engine de Voz e Telefonia (Twilio + Webhooks)
Abordagem AMD vs IA: Para garantir simplicidade máxima e alta performance (conforme solicitado), utilizaremos o Twilio Answering Machine Detection (AMD) nativo configurado na chamada (MachineDetection='DetectMessageEnd'). Se a Twilio detectar humano, a chamada é conectada ao fluxo de voz da IA; se detectar secretária eletrônica (machine_end_beep ou machine_end_silence), o sistema atualiza o status do lead imediatamente para caixa_postal e encerra a chamada sem desperdiçar tokens.

Media Streams / Conversação em Tempo Real: Reaproveitamento da infraestrutura WebSocket/TwiML existente no projeto para capturar o áudio do candidato/lead, enviá-lo ao STT (Speech-to-Text), processar a resposta da IA com base no contexto do produto via RAG, e converter o texto de volta em voz (TTS) para fluir na ligação de forma natural.

C. Pipeline RAG para Vendas
Quando a ligação é iniciada para um lead e vinculada a um produto/serviço, o agente de IA carrega dinamicamente o contexto comercial vetorizado no banco PostgreSQL (pgvector).

A IA utiliza esse contexto para argumentar, contornar objeções comuns ("está caro", "não tenho tempo", "já uso outro serviço") e conduzir o lead para o fechamento ou próximo passo (Call to Action).

D. Painel Administrativo (Streamlit)
Tela de Produtos: Cadastro/edição das informações dos produtos e serviços que a IA vai ofertar.

Tela de Leads (Fila): Importação ou cadastro manual de números e nomes. Um botão de disparo unitário (ou processamento da fila de 1 em 1) inicia a chamada via API da Twilio.

Tela de Relatórios/Histórico: Listagem de todas as chamadas realizadas, exibindo o status final do lead, áudio gravado e a transcrição completa da conversa estruturada em chat.
